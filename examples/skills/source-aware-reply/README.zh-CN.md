# 来源感知回复 Skill

这个原创合成示例以完整演示世界承载一个声明式回复 Skill。它的方法要求区分玩家明确说过的话、成立的来源和未知信息：无法确认时询问，不编造偏好、行动、感受或关系经历。示例描述预期行为，不代表真实模型效果评测。

文件遵循仓库的 [Apache-2.0 许可](../../../LICENSE)。清单记录作者、许可、版本、能力需求和来源/内容摘要。不包含私密案例、玩家历史、本地连接、凭据或运行状态。`assertions.json`用于阅读说明，不是测试通过报告。

## 在创作后台使用

服务端需要 **1.11.0 或更高契约**。在“内容与资源”中选择`source-aware-reply.wepkg`并读取预览，核对来源用途，明确选择本地 Mock 模型和已登记 TEXT 能力。本地匹配只读，不授予导入或运行权限。

导入为隔离草稿，在编辑器查看导演岗位、Skill 方法、合成示例及绑定。完成完整 Mock 试演、当前修订检查和来源用途审核，再批准隔离修订。发布是独立操作，生成不可变版本。分享时选择该版本，填写内容包标识、版本和公开作者，并确认复制与再分发权利后导出。第二套安装必须重新匹配、隔离、试演和审核；审核结果及本地模型配置不随包迁移。

Skill 使用 GENERATIVE/TEXT、`GenerationMaterial -> DispatchAuthorization`、TURN 触发、generation NONE、无工具、失败 BLOCK、预算归 PARENT。它向既有父任务提供方法材料，共用一次主文本及原来的修复槽，不安装可执行代码，也不单独购买模型调用。其他接口签名或伪装 PROGRAM 不获得运行权限。

## 重新生成静态文件

在仓库根目录使用支持的 Go 工具链：

```sh
go run ./cmd/wepkg-example ./my-source-aware-reply.wepkg
```

输出路径必须不存在。命令使用唯一的内容包构建器，核对内嵌清单和正文摘要，只写静态字节，不连接服务、不导入、不发布。提交的归档需要逐字节可复现。通常在后台编辑后重新审核导出；直接改源文件时，应主动同步清单、版本和摘要。正文中的叙事文字不会被当成本地标识自动替换。
