# Security Issues and Operating Scope

The current version is a development foundation. Before providing services to real users, deployment isolation, permissions, backup and recovery, data deletion and monitoring must be verified. Current check records do not represent production acceptance.

Do not submit tokens, passwords, cookies, actual connection strings, private conversations or exploit details in public Issues, logs or Pull Requests.

If GitHub private vulnerability reporting is enabled for the repository, submit through the repository's Security page. If it is not enabled, you may first make a contact request without vulnerability details, for the maintainers to arrange a private communication channel.

Reports should include the affected version, reproduction conditions, expected and actual behavior, and a redacted minimal example. Do not access other people's accounts, worlds, character memories or private data to verify an issue.

Treat model output, uploaded documents and community Skills as untrusted input. Model API keys are kept on the server; permissions and transactions must be checked by the program. The current demonstration mode does not call real models or charge real fees.
