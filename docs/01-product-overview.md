# Loreviva 产品概述

当前范围（2026-10-29）：Task1–8保留声明范围内采用；Task9已接通预览和持久隔离导入，隔离转出、导出/第二安装及Task9/R0整体尚未完成。工作契约1.8.0：70操作/192 Schema，迁移0001–0009。见[当前内容包验证](progress/2026-10-29-p3.zh.md)。

**The AI Platform for Living Worlds — 创造世界，让它持续生长。**

Loreviva 面向有明确背景与规则的互动世界：角色拥有稳定人格，依据自己实际获知的经历形成记忆、承诺和关系；世界事实由程序维护，AI 产生可检查的候选内容。

本文是现行产品规范的公开整理视图。以下愿景并不表示所有流程已经可用；本批实现状态见[需求说明](02-requirements.md)，安装范围见[搭建和接入](04-setup-and-integration.md)。

## 创作者要完成的事

目标流程是：选择模板或描述背景 → 编辑世界/角色/规则 → 绑定岗位、Skill、知识和模型 → 沙盒试演 → 固定发布版本 → 创建并运行实例。

World Studio 的目标包括表单、对象树、属性面板与 2D/2.5D Creator Canvas。本批 Task7 已实现原生 Vue 表单与 SVG 场景视图，让草稿编辑、场景位置、资源映射和关联影响可见；不据此宣称所有目标画布能力都已验收。它不承担完整 3D 引擎、通用 MMO 或 VR 工具链。角色预览仍需区分固定人格与外观设置、历史核准结果和新的随机演绎，不能偷偷改变运行事实。

每个生成模块都应提供可选的编辑助手和模型配置，普通表单仍可独立使用。AI 把背景文本转换成规则或提出修改时，创作者先查看差异和影响，采纳后仍显式保存；保存草稿、发布版本和创建实例是不同操作。

Task7 已把草稿编辑、可选 Mock 编辑助手、检查、发布、实例操作和隔离排练接入原生 Studio，并提供本地设置、成员操作与独立自同意入口。受控自动浏览器流程使用实际本机服务和合成 Mock 数据；它不等于真人可用性、真实模型质量或完整 R0 验收。候选仍受当前资格、路由、来源和输入校验约束，不自动保存草稿；排练不改写正式运行实例。

## 四类对象边界

| 对象 | 含义 |
| --- | --- |
| 世界项目/定义 | 制作容器及背景、场景、规则、角色等内容 |
| release | 固定的内容、依赖和生成路由版本；修改草稿不会改写它 |
| 世界实例 | 某个 release 的实际运行状态、事件与控制状态 |
| 角色模板/演员实例 | 可复用的人格定义，以及该角色在某个世界实例中的存在 |

复制模板或把同一角色放入另一个世界，不复制玩家身份、私人记忆、关系、运行事实或账务。实例升级需要独立预览和执行，不能通过重置历史消除不兼容。

## 角色,记忆与关系

角色的人格包括价值、目标、表达风格、知识边界和合理拒绝。玩家对角色说过的话、角色看到的公共事件与角色自己的推断需要保留来源，不能混成无条件事实。

共享世界可以共用演员的公共身份和已经见证的公共经历；每个玩家仍有独立的私有关系层。关系表达的是“角色如何理解目标主体”，不代表玩家真实心理，也不自动生成反向关系。

有读取权限还不等于角色已经获知，更不等于可以公开表达。私人来源的派生记忆与目标继承私有受众；撤权、纠正和删除需要阻断后续使用并继续清理，已交付副本不能承诺召回。

Tasks 1–6 已实现作用域、获知、治理和有界Mock互动内核；自动生成自然关系、持续人格成长与真实记忆效果仍需R1真实模型和真人证据。合成Mock测试不能代替这些效果验收。

## 岗位与 Skill

目标预设包括导演、编导、演员、化妆造型、表演声音、场务、记忆关系与质量评审。岗位可以兼任、替换或由程序承担，职责覆盖不要求每个岗位都调用模型。

Skill 是带版本、输入输出、来源许可、能力和成本边界的方法。通用与专用方法可绑定到不同岗位；社区导入不能安装任意工具、增加权限或绕过父任务预算。

在线生成目标默认是一名主要回应者的一次主文本生成，必要的结构修复或状态冲突重算共享最多一次额外文本调用。其他常规规划、评审和记忆整理不能各自新增文本调用。本批Mock Harness已按这一边界验证；真实模型调用与效果尚未验收。

## 内容组合与分享

世界、角色、导演/岗位、Skill、知识、表现资源与多个模型配置共同构成不同作品。模型连接属于可映射能力需求，内容包不能要求另一安装把数据发送到原作者地址。

计划中的 `.wepkg` 包含逻辑定义、素材、许可、依赖、合成样例和断言，排除秘密、玩家数据和运行状态。导入先做静态预检，再建立隔离草稿并试演；首期以文件和仓库目录分享为主，插件商业市场后置。当前已提供[格式 Schema](../contracts/source/wepkg.schema.json)，完整导入导出流程尚未实现。

## 行业与客户职责

| 目标客户 | 接入时需明确的业务边界 |
| --- | --- |
| 游戏平台/影游 | 世界动作、游戏资产、分支结果与客户端表现分别确认 |
| 情感应用 | 私人关系、同意、撤回、频率与联系方式边界 |
| 在线教育 | 学习目标、评价规则、受众和数据用途；不能把角色对白当权威评分 |
| 虚拟社区 | 共享事实与个人关系、成员资格、内容治理和通知渠道 |

引擎目标是承担世界、AI、记忆、预算和恢复，让客户专注交互产品。客户仍负责身份验证、用户资格、行业规则、玩家订单/钱包/支付/退款以及原业务服务的权威回执。行业适配和相关验收不能由通用内核的测试替代。

## 社区与托管路线

目标是社区自托管核心与托管服务共用内核。自托管不以平台充值或强制云服务为前提；托管计量需要区分供应商原始用量、平台服务额度和客户玩家业务余额。

Mock 原请求的结果、必要费用和额度记录已分开核验；本地设置与成员界面已纳入 Task7。真实模型、计量管理页面、账单/付款闭环、完整恢复及首个可收费发行门仍待实现与验证。当前 Mock 环境不提供生产 SaaS 或玩家收费能力。Task8已有接入实现但整体验收未完成；Task9静态预检之外的功能、Task10–12完整范围、LC长期效果、真人验证和完整发行仍待完成。
