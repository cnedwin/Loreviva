# 07 · 并发世界中的回合校验

## 前提

一个世界实例下会同时推进多个任务，它们互相影响：任务 B 提交的记忆或世界动作，会改变任务 A 之后读到的世界。因此"我提交时的世界与接收时不同"是**常态**，不是错误。

## 校验模型

一个原回合（original attempt）的生成证明在发送时冻结，由若干部件组成：

| 部件 | 覆盖 | 提交时要求 |
| --- | --- | --- |
| 来源身份 | 输入来源、回合命令哈希 | 完全相等 |
| 角色核心 | actor 的稳定核心字段（不含可变呈现） | 完全相等 |
| 技能输入 | 本回合允许使用的技能集合 | 完全相等 |
| 记忆集合 | 本回合**实际使用**的记忆节点（含正文、来源、归属） | 在原节点集合上重算后完全相等 |
| 世界感知 | 世界实例的可感知状态 | 相等，或原感知仍被允许 |
| 路由 | 生成路由 | 完全相等 |

总哈希（`ContextHash`）仍然记录并外显，但**不再作为唯一判等依据**：它会把"别人新增了一条我从未使用的记忆"也算成变化。

## 漂移的分类

| 分类 | 条件 | 处置 |
| --- | --- | --- |
| 无漂移 | 上表全部相等 | 正常提交 |
| 无关漂移 | 只有本回合未使用的记忆/来源被新增 | 正常提交；不进入恢复 |
| 引用漂移 | 被引用的记忆或世界资源发生变化，候选不再成立 | 返回候选资源冲突，进入重算与审批恢复 |
| 身份/授权漂移 | 授权、租约、预算、感知不再被允许 | 拒绝（403/409 语义不变） |

## 恢复

- 恢复基于已冻结的 provider 结果重算，会再次消耗一次调用，必须在审批记录中显式体现。
- **R0 限制**：恢复期间要求没有第三方提交介入。第三方在审批与提交之间提交，仍会得到冲突拒绝。解除该限制需要"漂移代数"，列入后续版本，不在 R0 声称支持。
- 出生记录接受"同源"的恢复基线（来源、核心、路由一致，上下文与世界哈希可不同），因为漂移正是由同一并发前提造成的。

## 隐私与治理

- 被引用记忆仍逐节点校验正文与来源；改写正文而修订号不变的情况**必须**被发现并拒绝。
- 同意、许可与受众每次读取都按数据库时间重新评估，不因本模型放宽。

## 状态

本模型已在 1.6.0 工作代码中实现（证明部件化、出生记录同源判定），并由 `TestIntegrationTurnMemoryProofFinalAndRecovery` 的正例（真实竞争者 → 冲突 → 重算 → 出生记录）与负例（改写被引用正文必须被拒）共同验证。
