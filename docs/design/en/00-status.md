# Design and Repository Support

Updated28 October2026.

Published long-form design views retain3.0.2; current product design is3.1.0 and R0 execution baseline is3.0.1. The design defines the full world-authoring, character, memory and customer-integration goals. The approved historical machine-contract baseline remains1.4.0 (58 operations,156 schemas, migrations0001–0007); this checkout contains the locally accepted Task8 implementation, with working contract1.6.0 (67 operations,181 schemas, migrations0001–0008). Current Task8 adoption covers its required interface projections and implemented routes, not product support for every1.6.0 operation. Reserved contract operations do not imply registered handlers. R0 support is the verified **Windows local fixed-volume** path: the durability and coordinator layer refuses to open a non-Windows volume, so unit packages and the maintenance journal are exercised on Windows only, while the tree must still build on Linux.

Task9 has `.wepkg` static-preflight interfaces and locally verified complete portable bodies, qualified logical references and deterministic pure mapping plans. Passing evidence covers 59 top-level unit targets (313 with subtests), 13 generator tests, 16 Go/AJV comparisons, four actual HTTP targets and actual Studio/Settings flows. Pure plans remain non-executable and grant no permission or local resource. Initial failures and bounded fixes are retained rather than described as one clean combined run. Persistent isolated import, rehearsal/local publish, export and whole Task9 remain unaccepted.

The SDK, thin backend, reference client and self-memory governance are included in Task8 local package acceptance, with platform and real-effect limits retained;1.6.0 as a whole, Tasks9–12, sustained character growth and24 long-term experience scenarios are still not delivered as a complete product. Real-model quality, human experience, the complete installation release, payments and deployment remain unaccepted. Known failures and not-run items for this batch are listed in the[progress note](../../progress/2026-10-28-portable-definitions.en.md); a documentation correction does not replace them.
