# Content-package manifest validation (2026-10-28)

Package preflight validates the complete manifest before decoding. Missing required fields, unknown members, wrong types, or invalid values produce a rejection report. Failed manifests do not enter downstream file or reference checks. Valid manifests retain compatibility, tool requirements, tested configurations, and provenance metadata.

The backend validator and embedded Schema are generated from the sole maintained wepkg Schema. Path expressions use the already locked regexp2 version with a 100 ms match limit; compilation, execution, or timeout errors reject the match. Default JSON handling keeps its 1 MiB limit. Manifest parsing and file-record digests use explicit limits so legal large manifests remain supported. Schema-valid decimal or exponent spellings of integers are converted exactly after validation, preventing partial decoded objects from escaping.

Reports use fixed descriptions, safe locations, bounded fields, and at most 32 deterministically sorted manifest diagnostics. Arbitrary input property names are not echoed. Package identity comes only from a successfully validated manifest, while rejection reports retain actual input digests. These changes do not relax path, permission, or package-format constraints.
