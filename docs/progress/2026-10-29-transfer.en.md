# Package review, export and installation transfer

Creators can export an authorized immutable static release as `.wepkg`, match models, capabilities and files in another installation, import an isolated draft, then review and publish it. The original installation's immutable release remains unchanged.

## Creator workflow

1. Select published content in Content and resources. Enter a package ID, version and public author name, verify copy and redistribution rights for every included definition and file, then generate and download the package.
2. Read the original package in the destination installation. Explicitly choose local models, registered capabilities, source uses and file audience. Extract declared files and upload them normally to READY assets before explicit mapping. Import does not install files or tools automatically.
3. Save an isolated draft and check its current revision. A world requires a genuine local Mock rehearsal with nonempty original inputs, committed results and every applicable assertion passing. An inapplicable custody rule does not block approval; an applicable unexecuted assertion is not a pass.
4. Enter a review note and approve the saved revision. Approval appends an identical-content revision while retaining protected origins. Run a fresh revision check and explicitly publish an immutable release. Editing, copying, restoring history or changing an effective model route invalidates the old approval; save an isolated revision and review it again.

## Interfaces and storage

| Action | Interface |
| --- | --- |
| Approve isolated revision | `POST /world/v1/admin/content-drafts/{draft_id}/isolation-approvals` |
| Generate static package | `POST /world/v1/admin/content-packages/exports` |
| Read export receipt | `GET /world/v1/admin/content-packages/exports/{export_id}` |
| Download original package | `GET /world/v1/admin/content-packages/exports/{export_id}/archive` |
| Extract declared original file | `POST /world/v1/admin/content-packages/file-bytes` |

Every interface uses current operator authority. The sole machine contract defines product queries and payloads. Retain the original key and input for writes; recover unknown outcomes with that same request. Downloads verify size and SHA-256. File-response metadata is bound to the bytes and grants no local use rights.

Export follows only schema-declared reference positions and the exact reachable dependency closure, preserving narrative text. Every included definition and file needs copy and redistribution rights. Another subject's private editor content, expired licences, private source addresses and source URLs with queries or fragments are refused. Creators must review free text; automatic checks are not semantic privacy clearance. Models carry capability requirements and representable parameters, without local connections, model identities, budgets or credentials. Existing PROGRAM Skill declarations retain registered capability mapping; arbitrary code, tool installation and the complete community Skill workflow remain outside scope.

Migration `0010` adds `content_package_adoptions` and `content_package_exports`; migration 1–9 raw bytes remain unchanged. Approval evidence, sources and physical files are rechecked in the final transaction, with file locks held until approval returns. ZIP bytes and their receipt commit in one command transaction. Every download rechecks current sources, authority and assets. Already delivered bytes cannot be remotely recalled. Backup and restore must include both new tables and their related records; complete recovery acceptance remains later operations work.

## Verified scope

Actual MySQL, HTTP and two independent installations cover normal file upload/mapping, new identities, an unchanged original release, genuine complete Mock rehearsal and partial-report refusal, applicability, revision/route binding, final physical corruption, expired checks, revocation and source-withdrawal rollback, lost-commit-reply recovery and migration retry. Real Chromium creator flows complete export, unknown-reply recovery, download, second-installation file upload, import, rehearsal, review and publication with zero page-script errors. Concentrated regressions cover projection, sources, capability declarations, deterministic archives and SDK response boundaries.

Initial compiler, fixture and browser-label failures and their repairs are retained. These are separately completed actual targets, not a claim of a first entirely green combined run. Concurrent throughput, cross-process faults, real-model quality, human experience, charging and deployment were not accepted. Working contract **1.9.0 has 75 operations / 197 schemas**; design 3.1.0 and R0 execution 3.0.1 remain separate. Safe document extraction, complete Skill sharing, Tasks10–12 and whole Task9/R0 remain incomplete.
