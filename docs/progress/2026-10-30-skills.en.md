# Source-aware reply Skill

This original, synthetic workshop world contains a declarative reply Skill. Its method keeps player statements, source evidence and unknowns separate: ask instead of inventing a preference, action, feeling or relationship event. The examples describe intended behavior; they are not measurements of a real model.

The files are shared under the repository [Apache-2.0 licence](../../LICENSE). The manifest records author, licence, version, declared capabilities and source/content digests. No private case, player history, connection, credential or runtime state is included. `assertions.json` is a reading aid, not a test result.

## Try the creator workflow

Use a server with contract **1.11.0 or later**. In Studio, open **Content and resources**, select `source-aware-reply.wepkg` and read the preview. Review the source rights and explicitly choose the local Mock model and registered TEXT capability. Matching is read-only and grants no import or execution authority.

Import as an isolated draft, open the editor and inspect the role, Skill method, synthetic examples and binding. Run the complete Mock rehearsal, check the current revision and approve it after reviewing its source/use rights. Publishing creates a separate immutable release. To share, select that release, supply a package identity/version/public author and confirm copy/redistribution rights before export. A second installation must repeat local mappings, isolation, rehearsal and review; approval and model configuration do not travel with the archive.

The Skill is GENERATIVE/TEXT, `GenerationMaterial -> DispatchAuthorization`, triggered by TURN, with generation NONE, no tools, BLOCK on failure and budget owner PARENT. It contributes method material to the existing parent task, with one text purchase and the original shared repair slot. It does not install executable code or create a separate model purchase. Other signatures and PROGRAM disguises do not gain runtime authority.

## Rebuild the static archive

From the repository root with the supported Go toolchain:

```sh
go run ./cmd/wepkg-example ./my-source-aware-reply.wepkg
```

The output path must not exist. This command uses the existing canonical package builder and the embedded authored manifest/definitions, checks their hashes and writes static bytes only. It never connects, imports or publishes. The checked-in archive must reproduce byte for byte. Normal creator edits belong in Studio followed by a new reviewed export; source edits require deliberately updating the manifest, version and hashes together. Changing narrative is never an implicit local-ID replacement.

## Verification boundary

The automated synthetic checks use this actual repository archive, two independent local installations, normal isolated approval/publication/export and real parent tasks. They verify remapped IDs, preserved method/examples, exact imported Skill hash/binding, a single parent text purchase and refusal before procurement for incompatible adapters. Real Chromium covers the creator import/review/export workflow. These checks do not establish real-model quality, emotional outcomes, a public marketplace, deployment, performance or commercial acceptance. Durable document extraction/adoption and whole Task9/R0 remain separate work.
