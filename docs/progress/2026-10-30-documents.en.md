# Safe document extraction preview

Creators can inspect authorized normally uploaded knowledge files with literal text, source locations, the original SHA-256 and explicit omissions. Preview retains source ownership/audience. It executes no script, macro, link or instruction, calls no model and creates no knowledge object, task or publication.

TXT/Markdown preserve original UTF-8 byte and line positions. DOCX validates OPC identity, relationships and namespaces and extracts ordinary body paragraphs/tables. Headers, footnotes, images, revisions, hidden text and unprocessed containers remain explicit gaps; pagination is never invented. PDF supports standard Type1 ASCII/WinAnsi text, classic xref and plain/Flate content streams. Actual trailer Root, page tree, object offsets, graphics/font state and stream boundaries are checked. Complex fonts, encryption, object streams and unsupported representations are refused or explicitly unsupported. Image scans require OCR; OCR is unavailable. Text preview does not promise visual fidelity.

Concurrent bounds: original8MiB, expanded16MiB, member4MiB, ZIP128 entries/ratio100, PDF200 pages,1000 chunks,512KiB extracted text and1MiB complete encoded JSON response including source/chunk metadata, escaping and final newline, within3 seconds. Exceeding any bound refuses safely. Missing content never becomes complete source evidence. The GUI presents format/size limits before selection.

`GET /world/v1/admin/document-capabilities` and `POST /world/v1/admin/assets/{asset_id}/document-preview` use current operator authority. Preview binds product and expected original digest and accepts only READY KNOWLEDGE assets. Source, audience, permissions and credential expiry are checked through reading/parsing and before response. GUI output is literal text; cancellation and source/product/credential changes invalidate late results. No reusable adoption capability is produced.

Actual verification covers four uploaded formats, scanned pages, unauthorized/cross-product reads, stale digests, withdrawn/corrupt sources, spoofed DOCX and encoded response bounds. Focused fixtures cover PDF structure/font state, OPC namespaces/hostile archives, cancellation and original positions. Real Chromium verifies visible limits, inert script/instruction text, source-change invalidation and explicit OCR requirements, with zero page errors. Initial compiler/admission/inventory failures are retained. Four independent review findings were repaired together and verified against current source.
