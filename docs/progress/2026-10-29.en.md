# Local dependency matching and package import preview

Creators can read a `.wepkg` in **Content and resources**, choose an entry point, review source permissions, and map external content, models, capabilities and files to the current installation. The form shows findings and an editing candidate. Cancellation or a changed selection clears previous results.

The endpoint is `POST /world/v1/admin/content-packages/preview?product_id=...`. It accepts an operator bearer, `Idempotency-Key`, and exactly two multipart parts: `archive` and `options`. `DISCOVER` returns package declarations for the mapping form. `RESOLVE` checks explicitly selected local releases, objects, hashes and uses against current authority. Portable logical IDs, semantic versions and hashes are never cast into local identities or revisions.

External references must match an available immutable release in the current product. Checks include reference kinds, complete source closure, edit and copy uses, audience, expiry, and existing file state, ownership, hash, size and MIME type. Explicit model requirements and inherited settings remain distinct. R0 currently supports only the installed Mock text model; disabling it blocks new candidates.

Responses are `NEEDS_MAPPING`, `RESOLVED` or `BLOCKED`. Both `execution_ready` and `persisted` are always `false`. Inspection rolls back its transaction and rechecks credentials and sources before returning a candidate. A report grants no import authority or permission for a later command. It creates no draft, business receipt, model task or release. Refusals contain no partial candidate.

## Verified scope

- All 12 directly affected unit targets (17 including subtests) passed. The capability table agrees with the generated contract.
- Six actual MySQL HTTP targets (21 including subtests) passed, covering matching, incorrect kinds and hashes, source uses, withdrawal, final credentials, file checks, inherited and explicit model disablement, and transitive source uses.
- A real creator-browser flow read the archive, selected a dependency, mapped the Mock model and text capability, displayed a candidate, cleared changed selections, and cancelled a late response. Inspected business-row counts remained unchanged.
- The two model-disablement scenarios used independent fixtures, first obtaining a valid candidate and then confirming refusal after disablement. Initial failures and their fixes remain recorded; this is not described as one clean combined rerun.
- Studio was rebuilt from current sources. The working contract is 1.7.0 (68 operations and 189 schemas). Product design 3.1.0 and R0 execution 3.0.1 remain separate baselines.

Persistent isolated import, recoverable import records, export and transfer to a second installation remain pending. A separate real subject or product, transitive-source expiry races, real model quality, human experience, performance, charging and deployment were not accepted in this scope.
