# 内容包清单校验（2026-10-28）

内容包预检在解码前校验完整清单。缺少必填项、未知字段、类型错误或非法值会返回拒绝报告；失败清单不再进入后续文件和引用检查。有效清单保留兼容性、工具要求、测试配置与来源信息。

后端校验器及其嵌入的 Schema 均由工程唯一维护的 wepkg Schema 生成。路径正则使用已有锁定版本的 regexp2，并设置100毫秒匹配上限；编译、执行或超时错误均拒绝匹配。原有默认 JSON 限额维持1 MiB，清单和文件记录摘要使用显式限额，支持格式允许的大清单。合法整数的小数或指数写法在通过 Schema 后进行精确转换，避免部分对象泄漏。

错误报告采用固定说明、安全位置和有界字段，最多保留32个稳定排序的清单诊断。任意输入属性名不进入报告；包身份仅来自成功校验的清单，拒绝报告保留实际输入摘要。以上处理不放宽路径、权限或内容包格式。

验证结果：

- 先实际复现清单准入、超出1 MiB的合法摘要输入、错误报告及生成产物缺失；后续补充的诊断回显与整数转换失败也保留原始结果。
- 受影响 Go 单元测试32个顶层目标、含子项139项全部通过，未跳过。覆盖完整字段、依赖边界、正则超时、32项稳定选择和大清单。
- 生成器7项回归通过；生成产物检查无差异。
- 四项实际 MySQL HTTP 集成目标全部通过，覆盖合法包与重复预检、完整拒绝报告、请求格式和能力限额。接口响应符合 Schema，所检查业务表行数保持不变。
