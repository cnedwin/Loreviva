## Shard runner repair

The old runner could succeed after child compilation failure or without target terminal evidence; serial retry inferred success from absent failure text. The runner now checks every planned target, the package terminal, exit code, signal and evidence completeness. stdout and stderr are separate and fully flushed. Only complete named test failures can be retried serially; an explicit pass is required, so missing results, skips or process errors cannot erase failures.

Exit0 means complete initial pass/skip evidence; skips are not product passes. Exit1 means failure or incomplete evidence. Exit2 means serial-only recovery, retaining initial failures for review. summary.json records targets, initial outcomes, retry and per-attempt evidence. Extra empty shards are avoided and invalid arguments are rejected. Local scripts and Windows/Linux byte CI include the regression suite.

All25 synthetic child-process regressions passed, covering nonzero exits, missing results, package failure, truncation, signals, spawn failure, duplicate/foreign results, retry failure/skip, shard arguments and serial recovery. Further checks are recorded against the fixed candidate; these checks establish the tool repair, not database integration or product acceptance.
